# ThreatCapital: GhostGrid

ThreatCapital: GhostGrid is a hackathon-ready cybersecurity demo that combines external risk quantification with an active deception environment. A defender can assess a domain, while a simulated attacker explores a decoy SMB shell and receives synthetic responses generated by the deception engine.

## What It Demonstrates

- Layer 1: Cyber risk scoring from SPF, DMARC, exposed ports, and breach indicators.
- Layer 2: A simulated attacker shell with `ls`, `pwd`, `cat`, and `search` commands.
- Active deception: Search requests can generate synthetic honeyfiles and canary content.
- Live defender telemetry: The defender console follows the most recently active attacker session through the shared backend.
- Cross-device demo: The attacker and defender consoles can run on separate laptops on the same network.

## Architecture

```text
Attacker browser (?mode=hacker) --\
                                  > FastAPI session store and deception engine
Defender browser ---------------/
        |
        +--> React/Vite console with Layer 1 risk gauge and Layer 2 attack feed
```

The backend keeps active Layer 2 sessions in memory. Run one backend instance for a multi-device demonstration; both browsers must connect to that same backend.

## Requirements

- Python 3.10 or newer
- Node.js 18 or newer and npm
- Windows PowerShell commands are shown below
- Optional `GEMINI_API_KEY` in `.env` for Gemini-generated honeyfile content

## Installation

From the repository root:

```powershell
.\venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt

Set-Location frontend
npm install
Set-Location ..
```

If PowerShell blocks script activation, use the virtual-environment interpreter directly:

```powershell
.\venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

## Run Locally

Open two PowerShell terminals from the repository root.

Terminal 1, backend:

```powershell
.\venv\Scripts\python.exe -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Terminal 2, frontend:

```powershell
Set-Location frontend
npm run dev -- --host 0.0.0.0
```

Open the defender console at the Vite URL, normally:

```text
http://localhost:5173/
```

Open the attacker console at:

```text
http://localhost:5173/?mode=hacker
```

Backend API documentation is available at:

```text
http://localhost:8000/docs
```

## Two-Laptop Demo

1. Start the backend and frontend on the host laptop with `--host 0.0.0.0`.
2. Find the host laptop's Wi-Fi IPv4 address:

   ```powershell
   ipconfig
   ```

3. On the defender laptop, open `http://<host-ip>:5173/`.
4. On the attacker laptop, open `http://<host-ip>:5173/?mode=hacker`.
5. Run commands such as:

   ```text
   ls
   cat employee_payroll_2026.csv
   search invoice
   ```

The defender Layer 2 panel refreshes from the shared backend about once per second and updates penetration depth, attacker intent, confidence, deception output, recommendations, and prevented exposure.

If another device cannot connect, allow Python and Node through Windows Firewall and confirm both laptops are on the same network.

## API

### Layer 1 scan

```http
GET /api/v1/scan?domain=example.com
```

Returns the Cyber FICO score, rating, financial exposure, SPF and DMARC results, open ports, breach indicators, and Layer 1 sub-scores.

### Layer 2 command

```http
POST /api/v1/bubble/action
Content-Type: application/json

{
  "session_id": "ghost-sess-demo",
  "command": "search payroll"
}
```

The response includes command output, penetration depth, intent classification, confidence, generated filename, prevented exposure, and activity metadata. An empty command returns read-only telemetry for an existing session.

### Active sessions

```http
GET /api/v1/bubble/sessions
```

Returns active session summaries. The defender uses this endpoint to follow the latest attacker session.

## Verification

Run the frontend checks before submission:

```powershell
Set-Location frontend
npm run build
npm run lint
```

The application uses deterministic fallback behavior when external DNS services or Gemini are unavailable. This keeps the demo usable offline; setting `GEMINI_API_KEY` enables the Gemini honeyfile generation path.

## Troubleshooting

- `WinError 10048` on port 8000: another backend is already running. Stop it or reuse the existing instance.
- Blank or stale frontend: restart Vite and hard-refresh the browser.
- Layer 2 not updating: confirm both browsers use the same host URL and that only one backend instance is serving the demo.
- Gemini unavailable: verify `GEMINI_API_KEY`; the built-in synthetic fallback remains available.
